# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Star Viper is a Godot 4.7 (GDScript) horizontal roguelite shoot-'em-up. Nearly every asset is generated in code at startup: sprites, bosses, SFX and most of the music. The only binary assets are the bitmap font in `assets/fonts/` and Matthew's recorded songs in `assets/music/` (MP3s, see **Recorded tracks** under Asset generation). Gameplay and controls are described in `README.md`. `PROJECT_CONTEXT.md` and `AGENTS.md` repeat this material for other agents (Antigravity).

## Commands

`godot` below means the Godot 4.7.x editor binary. On macOS that is `/Applications/Godot.app/Contents/MacOS/Godot`.

```bash
godot --headless --path . --import                         # run once on a fresh clone, or after adding a class_name script
godot --headless --path . --quit-after 30 -- --smoke-test  # must print STAR_VIPER_SMOKE_TEST_PASSED with zero script errors
godot --path .                                             # play the game
```

- There is no unit-test framework or linter. The smoke test is the only automated check. It is `_run_smoke_test()` in `scripts/main.gd`, and it drives every menu, ship, upgrade, stage and boss by calling private methods directly. It mostly checks for crashes and script errors, not behavior; the skill-tree checks (save migration refund, locked draft cards, every node buyable, draft-card perk effects), the ship checks (`_smoke_check_ship_shots`: every ship's sprites, shot preview and tree icon exist; every signature weapon, option shot and the prism fly straight, are freed just past the screen edge or at the end of their short life, and keep their heading through a hit, since player shots never bounce; `_smoke_check_new_weapons`: the beam stops at the edge or the first enemy, the katana cuts only its arc, the tongue has a reach, seed sentries are capped and shoot, orbs swallow shots, rockets burst, ripples grow; `_smoke_check_ship_runs`: every ship's hull, speed and perk, its weapon fires, a drafted beam mounts and fires; plus the scrolling loadout roster), the speed-up checks (`_smoke_check_speed_up`: hold, toggle, drop to 1x on every way out of flight, setting saved and loaded), the sub weapon check (`_smoke_check_sub_weapons`: drafting picks the sub weapon, `E` / pad `B` cycle the owned ones and wrap, only the active one fires or flies, a hull perk's addon starts active), the tree checks (`_smoke_check_tree_knowledge`: every node on its ring, no ring can lock, a fresh tree shows ring 1 only, the 4th rank opens ring 2 and plays the growth reveal, the cursor never enters the fog; `_smoke_check_tree_draw`: the canvas draws at rest and pulled back mid-reveal), the evolution check (`_smoke_check_sub_evolutions`: run start reads the marks, and missiles, turret, flank guns, bombs, aux beam, blades, nova and options change at MK IV and not when stock) and the stage-enemy checks (`_smoke_check_themed_enemies`: every sprite exists, every type runs its pattern, a kill pays out once, child spawns are capped and give no Scrap, the golem shield, frost/bomb/spore shots, the difficulty table only gets harder) and the stage-module checks (`_smoke_check_stage_modules` and `_smoke_check_module_draws`, see **Adding a stage**) instead push an error and exit 1 without printing the PASSED line. If you rename a method it calls, update it there. If you add a ship or upgrade, add it to the smoke test; stage enemies are picked up from `GameEnemy.THEMED` automatically, and stage modules from `scripts/stages/registry.gd`. The last checks need real frames (draw hooks only run in a frame's draw pass), so PASSED is printed a couple of frames after the rest of the test, from `_smoke_finish`.
- **The smoke test overwrites the real save file.** It buys skill-tree nodes and finally calls `MetaSave.reset_save()`, all against `user://star_viper_save.json`, the same file normal play uses. Back that file up before running the test on a machine where someone has progress.
- `build_releases.bat` (Windows only) copies the Godot editor binary next to an exported `.pck`. It has the original author's Godot install paths hardcoded. `export_presets.cfg` has `Windows` and `SteamDeck` (Linux) presets.

## Code conventions

- Use explicit static types everywhere. Don't use `:=` when the right-hand side is a `Variant`, such as a `Dictionary` lookup or an element of an untyped `Array`. Cast instead, for example `String(d["id"])` or `int(d.get("x", 0))`. The codebase does this consistently.
- Nearly the whole scene tree is built in code. `scenes/main.tscn` contains a single `Node2D` with `main.gd`, and all UI is laid out with literal pixel coordinates. Don't go looking for `.tscn` files or a theme resource.
- Input is polled directly with `Input.is_physical_key_pressed(KEY_*)` and joypad button and axis checks, in `player.gd` and in `main.gd` (`_unhandled_input`, `_poll_controller_menu_stick`, and `_update_speed_up` for the speed-up button: `F` or the right trigger, which is not a fire button), plus `player._unhandled_input` for the sub weapon swap (`E` or pad `B`). The project defines no InputMap actions. Touch and mouse-drag flight is handled in `player.gd`.
- On-screen button prompts follow the last device used. `InputPrompts` switches between keyboard/mouse and gamepad on each real press (stick drift and small mouse nudges are ignored) and draws key caps or Xbox button glyphs. Never write key names into UI text. Use `InputPrompts.bind_button(btn, action)` for a button, or a `PromptBar` (`scripts/prompt_bar.gd`) for a line of text with glyphs. Actions are listed in `InputPrompts.ACTIONS`. If you change a binding in `_unhandled_input` or `player.gd`, update its entry there too.
- Menu focus: the Options panel sets explicit focus neighbours with `_link_focus_grid(rows)`, because Godot's automatic search picks wide neighbouring rows over the button beside you. Use it for any new grid of buttons. The left stick is removed from the `ui_left/right/up/down` actions in `main._ready`, so `_poll_controller_menu_stick` is the only stick handler and one push moves focus once. RESET SAVE needs two presses within 3 s.
- Text uses the FF6-style bitmap font at `font_size = 10`, or an integer multiple of it. Texture filtering is nearest-neighbor and antialiasing is off.

## Screen layout (480×270 native, integer-scaled)

- `y 0–19`: top status bar, drawn by `main._draw_hud` on `hud_bar`. Its "S-W NAME" label runs from x 158 to the SCRAP counter at x 294; `_fit_hud_stage_text` drops words from the end of the stage name when it doesn't fit (two-digit stage numbers, loops). `y 19–23`: XP bar. `y 24–33`: at `x 2–70` the active sub weapon (badge, name, and the swap button glyph once 2+ are owned); at `x 72–390` the boss HP gauge, one solid bar in the phase colour with a pale strip that drains behind it after hits and marks at the phase thresholds (only shown during a boss fight; `main._boss_bar_lag`); at `x 436–476` the speed-up `>> x2` badge while 2x is on.
- `y 30–249`: playfield. The player is clamped to `PlayerShip.MIN_Y`/`MAX_Y`. Player shots never bounce: they fly straight and are freed just past the screen edge (`GameBullet.PLAYER_SHOT_BOUNDS`).
- `y 258–270`: scrolling floor deck, drawn by `StarfieldBg`. There is no bottom HUD.

## Architecture

**Autoloads**, in load order:

| Autoload | Role |
| --- | --- |
| `MetaSave` | Persistent progression and settings. |
| `StageData` | Stage table: the 8 built-in stages plus every registered stage module, × `WAVES_PER_STAGE = 4`. Wave 4 of each stage is the boss. Never assume 8 stages: use `stage_count()`, `wrap_stage()` and `loop_of()`. |
| `PixelArt` | Texture cache. |
| `RetroSfx` | Pool of synthesized `AudioStreamWAV` effects. |
| `GenesisMusic` | Real-time synth that feeds an `AudioStreamGenerator`. |
| `InputPrompts` | Tracks the last-used input device and builds the button-prompt glyphs. |

`SkillTreeData` is a `class_name` with const data only (`SHIPS`, `NODES`). It is not an autoload.

**`main.gd` is the hub** (about 2,750 lines). It owns the `State` enum state machine, builds every menu panel, runs the wave director (`_begin_next_wave` queues timed spawns into `_spawn_queue`, and `_update_wave_director` releases them), handles XP and level-up drafts, and draws the HUD, skill tree and pause screen. It does the drawing through `Control.draw.connect(...)` callbacks.

World layering is `world_root` → `pickup_layer`, `enemy_layer`, `player`, `bullet_layer`, `fx_layer`. UI lives on a separate `CanvasLayer`.

**Pausing and drafts don't use `get_tree().paused`.** They set `world_root.process_mode = PROCESS_MODE_DISABLED` and slow `starfield.speed_scale`. `GenesisMusic` runs with `PROCESS_MODE_ALWAYS` and is only ducked. Anything new that should freeze during pause must live under `world_root`.

**The speed-up button uses `Engine.time_scale`.** `main._set_speed_up` sets it to 2 and doubles `Engine.physics_ticks_per_second`, but only in `PLAYING` and `HYPERSPACE`. The `state` property's setter calls `_on_state_changed`, which drops back to 1x on any other state, so always change state through `state = ...`. Everything driven by `delta` speeds up; audio doesn't (music renders by buffer space, SFX keep their pitch). Because movement happens in `_process`, a 2x frame moves things twice as far between overlap checks: `GameBullet._update_sweep` adds a capsule along each shot's path while `time_scale > 1` (and when Options → FPS caps the game at 30, which makes frame steps just as long), and `GamePickup` uses `move_toward` so a pull can't overshoot the ship. Anything new that moves fast or tests distance once per frame needs the same care. Cooldowns that reset to their interval (rather than carrying the remainder) fire up to one frame late each time, so at 2x the player fires about 7–16% fewer shots per game second than at 1x.

**Entities are created with `.new()` and set up through a `setup(...)` call.** The player, enemies and bullets are `Area2D` subclasses; `GamePickup` is a plain `Node2D`. They talk to `main` through signals: `GameEnemy.destroyed(enemy, killed_by_player)`, `boss_phase_broken`, `spawn_requested` (child enemies), `GamePickup.collected`, `PlayerShip.hp_changed` and `player_died`.

- Collision layers: `1` player, `2` player bullets, `4` enemies, `8` enemy bullets. Pickups don't use physics: they are collected within 13 px of the player and pulled in from `MetaSave.get_magnet_radius()`.
- Enemies join the `"enemies"` group. Homing, chain and AoE effects iterate that group. A stage enemy that is still telegraphing its entrance (`_warn_timer > 0`: a lava blob bubbling, a jet's warning arrow) stays out of the group and has no collision until it appears.
- An enemy that leaves the screen emits `destroyed(self, false)`, and so does a space mine that bursts on its own. Only `true` awards score, Scrap or XP; an enemy with `scrap_drop` 0 gives no Scrap.
- Pickups spawned from kill handlers go through `call_deferred` (`_spawn_pickup_deferred`), because the kill happens inside a physics callback.

**Two progression layers:**

1. **Meta (between runs).** Skill-tree nodes live in `SkillTreeData.NODES`. Each node has an `id`, a `parent`, `max_level`, `base_cost` plus `cost_step`, a tree `pos`, `unlocks_ship` and `unlocks_upgrade`. `MetaSave.tree_levels[id]` stores the rank. **The tree deliberately gives no combat bonuses at run start** (Matthew's design call): nodes only add starting hull and shields, Lazarus revive, ships, economy perks (magnet, Scrap, XP, boss bounty, rerolls), "DRAFT CARD" nodes whose `unlocks_upgrade` adds a `RUN_UPGRADE_POOL` id to the level-up drafts, and "EVOLVE" nodes (see below) that only change a sub weapon once it's drafted.
   - **Rogue Legacy-style rings and fog** (Matthew's request). The tree is laid out in rings around the core: a node's ring is its depth (`SkillTreeData.get_ring`), and its `pos` must sit on that ring (radius `ring_radius(ring)`, inside its wing's sector: hull & shields up, weapon mods right, scrap & XP down, weird lab left; the smoke test checks the radius). A node shows, and can be bought, only once its parent is owned and its ring is open (`MetaSave.is_node_revealed`; `is_node_visible` adds owned nodes). Rings open with **Knowledge**: every rank bought adds 1, and reaching `MetaSave.KNOWLEDGE_LEVELS[L - 1]` opens ring L (one entry per ring). The ranks in the rings already open must always reach the next threshold, or the tree locks; the smoke test checks that too. In the hangar (`main._draw_skill_tree_canvas`) everything past the open radius is fog, conduits from owned nodes run into it, and the core citadel grows a ring of towers per Knowledge level. A purchase that raises the level plays the growth reveal (`_start_tree_growth` / `_update_tree_view`: the view zooms out, the fog rolls back while the new nodes pop in, then it zooms back; any input skips it). The cursor and clicks only reach visible nodes.
   - **EVOLVE nodes** (`"evolves"`: a `player.SUB_WEAPONS` id, 3 ranks = MK II-IV, `"rank_desc"` per rank for the inspector) sit in the outer rings, one per sub weapon. `PlayerShip.reset_for_new_run` reads them into `sub_evo` (`MetaSave.get_sub_evolution`), and each sub weapon's code checks `evo(id)`; the HUD shows the marks as pips after the sub weapon's badge. Effects are applied only through `MetaSave.get_*()` getters, such as `get_starting_max_hp()`, read by `PlayerShip.reset_for_new_run()` and `main._start_run()`. Ship perks are hardcoded by ship id inside the getters, for example `selected_ship == "phantom"` adds +20% crit.
   - **Saves:** `MetaSave.migrate_tree_levels()` runs on every load. It refunds Scrap for levels in nodes that no longer exist (priced from `LEGACY_NODE_COSTS`) and for levels above a node's current `max_level`, then drops unknown keys. If you remove or shrink a node, add its old price to `LEGACY_NODE_COSTS` so players get their Scrap back. `TREE_VERSION` is written to the save.
2. **Run (in-run drafts).** `main.RUN_UPGRADE_POOL` defines draft cards (`id`, `cat`, `max_rank`, `icon`). The base cards (BEAM, ADDON, CORE) are always offered. The 18 DRAFT CARD entries (cat MOD, GUARD, TECH or LOOT, plus `short` and `badge` for the pause screen) are skipped by `_roll_draft_choices` until `MetaSave.is_run_upgrade_unlocked(id)`. Choosing a card increments `main.run_ranks[id]` and calls `player.apply_run_upgrade(id)`. That function's `match` has **its own hardcoded rank caps**, which must stay in sync with `max_rank`. Once a non-vulcan ship drafts a beam, it is mounted as `aux_beam` while the signature weapon stays. On the vulcan ship (`viper`) the beam replaces `active_beam`. Either way, `_roll_draft_choices` then only offers that one beam.
   - **One sub weapon at a time** (Matthew's call). The ADDON cards (option, blades, turret, missile, flank, bomb, nova) and an exotic ship's `aux_beam` ("beam") are sub weapons, listed in `player.SUB_WEAPONS`; only `player.sub_weapon` fires or flies (`is_sub_active(id)` gates each addon's block in `_process`, its hull hardware in `_draw`, options via `_live_option_count()` and blades via `_active_blade_count()`). Drafting one switches to it; a hull perk's addon starts active; the swap button cycles the owned ones (`swap_sub_weapon`: `E`, pad `B`, the touch SWAP button above FOCUS; InputPrompts action `swap_weapon`). The main gun and every CORE / MOD / GUARD / TECH card stay on. A new addon needs a `SUB_WEAPONS` entry, a `sub_weapon_level` / `sub_weapon_name` branch, an `is_sub_active` gate, a `badge_<id>` texture and an EVOLVE node with its three marks wired through `evo(id)` (the smoke test fails a sub weapon without one); the pause screen dims inactive ones (`main._sub_module`).
   - DRAFT CARD effects live in `player.gd` (`_update_run_perks` for timed/aura effects, `_spawn_player_bullet` / `_spawn_mode_shot` for per-shot flags, `on_enemy_killed` and `on_stage_cleared` hooks called from `main`), `bullet.gd` (`_apply_hit_modifiers`, shrapnel fragments, mine lifetime, chrono slow) and `enemy.gd` (`apply_chill`, `apply_burn`). Anything that adds an `Area2D` from inside a collision callback goes through `call_deferred`.

**Enemies and difficulty.**

- Four generic types (`SCOUT_SINE`, `SWOOPER`, `SNIPER`, `CRUISER`) appear in every stage, re-skinned through the stage's `"scout_tex"` etc. (on stages 9+ they behave like the later built-in stages: spread-firing snipers, 4-shot cruisers). Each built-in stage also has its own enemies (the rest of `GameEnemy.Type`; stage-module enemies are all `Type.MODULE`, see **Adding a stage**), with base stats in `GameEnemy.THEMED` (home `stage`, `hp`, `score`, `scrap`, `xp`, hit `r` or `box`, `tex`). Their behaviour is one `_tick_<name>` per type, dispatched from `_process_themed`; per-type setup is in `_setup_themed`; telegraphs (charge glints, lock-on lines, warning markers, the glitch's ghost) and HP bars are drawn in `_draw_themed`, on top of the sprite (`show_behind_parent`). By stage: 1 asteroids (split into `ROCK_CHUNK`s) and mine layers (drop `SPACE_MINE`s); 2 floor/ceiling turrets and security drones; 3 bomber blimps and jet formations (some from behind); 4 spore pods and charging beetles; 5 ice crystals (shatter into shards) and snow drones (frost puffs slow the ship via `PlayerShip.apply_frost`); 6 leaping lava blobs and shielded rock golems; 7 jellyfish, eels (solid body segments) and anglerfish; 8 replicating viruses, teleporting glitches and firewall columns.
- **Difficulty curve:** `StageData.DIFFICULTY` has one row per built-in stage (modules add theirs): `hp`, `shot_speed`, `fire_rate`, `groups`, `pace`, `themed`. Stage 1 is all 1.0. Enemy HP actually scales by `1.34^stage_index` in `_begin_next_wave` (the `hp` column documents that curve). `get_difficulty()` wraps it for loops (HP x`loop_hp_step()`, plus a little more speed). Regular enemies' bullet speeds and cooldowns in `enemy.gd` are written as stage-1 values: `_shoot_from` / `_emit_bullet` scale speed by `shot_speed`, and `_fire_cd()` divides cooldowns by `fire_rate`. Bosses ignore the table.
- **Wave director:** in a regular wave, `_begin_next_wave` builds `groups` (+1 per later wave) groups, a `themed` share of them from `_queue_themed_group` (per-stage recipes; recipe C from the stage's second wave, an extra unit in the third) and the rest from the six generic patterns in `_queue_generic_group`. Each group's time gap is multiplied by `pace`.
- **Child enemies** (rock chunks, mines, virus copies) are requested with `spawn_requested`; `main._on_enemy_spawn_requested` puts them in `_spawn_queue` so they spawn next frame (never inside a physics callback) with signals connected, and the wave can't end while they're pending. Children (`gen > 0`) give no Scrap and at most 1 XP, and every source is capped: `ROCK_CHUNKS` per asteroid, `MINES_PER_LAYER`, `VIRUS_MAX_GEN` and `VIRUS_CAP`. Shots fired while dying (ice crystal shards) use `_emit_bullet(..., deferred = true)`.
- Enemy shot extras in `GameBullet`: `home_target`/`home_time`/`home_rate` (spores), `floor_burst` (blimp bombs), `make_frost()` (harmless puffs that slow the ship, never count as grazes), and any enemy shot with `life_left` fades out over its last 0.5 s.

**Content touchpoints.** Adding content means editing several files:

- **Ship:**
  - an entry in `SkillTreeData.SHIPS` (newer ships also set `badge` / `badge_name`, which label the weapon on the pause screen)
  - a `NODES` entry with `unlocks_ship`
  - sprites `<sprite_0>` and `<sprite_1>`, the shot and the badge: the original 7 are in `PixelArt._build_all`, the 10 newer ones in `ShipArt` (`scripts/ship_art.gd`, listed in `ShipArt.KEYS`)
  - a weapon branch in `player._get_mode_params` and `_spawn_mode_shot` (`_fire_primary` drives every weapon's volleys, spread and options). Weapons that hit without a bullet (beam, katana, tongue) return null from `_spawn_mode_shot` and deal damage through `_direct_hit`, so crits and on-hit DRAFT CARDs still apply. Weapons that only work from the hull go in `SELF_AIMED_WEAPONS` with an `_option_mode` projectile for the options. New ships fire a drafted aux beam on a 0.34 s timer; only the original 7 (`VOLLEY_AUX_WEAPONS`) fire it every 2nd volley
  - any perk inside a `MetaSave` getter; a built-in addon or DRAFT CARD rank goes in `get_starter_addons` (keys are `RUN_UPGRADE_POOL` ids, so draft caps count it) and is applied in `player.reset_for_new_run`
  - nothing in the hangar: the Fleet Loadout roster scrolls (`LOADOUT_VISIBLE` slots on screen, page arrows, wrap-around), and `_smoke_check_ship_shots` / `_smoke_check_ship_runs` pick the ship up from `SHIPS`. Add a perk line to `_smoke_check_ship_runs` and a mechanic check to `_smoke_check_new_weapons` if the weapon does something new
- **Draft upgrade:**
  - `RUN_UPGRADE_POOL`
  - `player.apply_run_upgrade`
  - an icon texture (`upg_<id>`; DRAFT CARD art is built from the badge in `PixelArt._build_draft_card_icons`)
  - for base cards, the badge list in `main._collect_installed_modules`, which feeds the pause screen (DRAFT CARD entries are listed automatically from `short`/`badge`)
  - for a tree-unlocked card, a `NODES` entry with `unlocks_upgrade` set to the card id
- **A new stage (9+):** a stage module, see **Adding a stage** below. It touches no shared file except its line in `scripts/stages/registry.gd`.
- **Built-in stages 1–8** keep their original code paths, which stage modules never edit: the `StageData.STAGES` and `DIFFICULTY` rows, `GameEnemy.STAGE_BOSS_HP`, boss patterns in `GameEnemy._boss_attack` (`match stage_idx`), the boss's look (an animated rig in `scripts/bosses/`, see **Animated bosses**; `BossPainter`'s frames are no longer used by the fights), biomes in `scripts/starfield.gd` + `scripts/stage_bg_painter.gd`, songs in `GenesisMusic.STAGE_SONGS` (plus a `"stage_N"` slot with 5 alternatives in `music_candidates.gd`; the smoke test expects 5 per built-in slot), and their enemies: a value appended to `GameEnemy.Type` (append, so queued spawns keep their meaning) with a `THEMED` entry, setup in `_setup_themed`, a `_tick_<name>` dispatched from `_process_themed`, telegraphs in `_draw_themed`, death effects in `_on_themed_death`, sprites in `EnemyArt` (listed in `EnemyArt.KEYS`), recipes in `main._queue_themed_group`, and for child spawners a cap plus `gen > 0` rewards (`_apply_child_rewards`).

  After the last stage, play loops back to stage 1 with harder enemies (however many stages there are); nothing ends the game.

**Asset generation:**

- `PixelArt` sprites are arrays of strings, one character per pixel, mapped through `PALETTE` or an optional custom palette passed to `_make_tex`. `BossPainter` draws bosses into `Image`s and registers three animation frames per boss, `boss_<theme>_0`, `_1` and `_2` (no longer used in fights now that every built-in stage has a rig; stage modules paint their own boss frames).
- **Animated bosses** (`scripts/bosses/`, Matthew's request: more life, and every boss piloted by an angry space dinosaur). A built-in stage listed in `boss_rigs.gd` gets a rig instead of the painted frames: `GameEnemy` adds it under `_sprite` (whose texture is then null, so the intro squash, recoil, sway and white hit flash still apply to every part, via `use_parent_material`), and calls `on_attack(pattern)`, `on_hurt()`, `on_phase(p)`, `on_pose()`, `on_die()` and, as the boss is freed, `eject(fx, fx)`. Boss shots leave from the rig's named muzzles through `GameEnemy._bm(name, fallback_offset)` (`_shoot_ring`, `_shoot_spread` and `_shoot_aimed` look for `ring`, `spread` and `aimed`), so they come out of the moving cannons, claws and jaws.
  - `boss_rig.gd` is the base: a subclass paints and assembles parts in `build()` with `part(parent, tex, joint, pivot, z)`, `joint()`, `marker()` and `add_pilot()`, and moves them in `animate(delta)` from `t`, `windup` (0→1 over the 0.42 s before each attack; `next_pattern()` says which attack is coming), `kick`, `hurt_k`, `rage`, `pattern` and `phase()`. **Never use `z_index`** for parts: anything below z 0 draws behind the stage background. `z` in `part()` picks one of 9 layer nodes for parts on the rig, or `show_behind_parent` for parts on a part.
  - `boss_kit.gd` paints the parts (flat shapes, then `shade()` rims and `outline()`), cached by key on first use. `dino_pilot.gd` is the pilot in its glass canopy: species `rex`, `raptor`, `ptero`, `trike`, `stego`, `spino`, `plesio`, `dilo` × faces `angry`, `blink`, `roar`, `hurt`, `panic`; it roars on attacks and phase changes, winces on hits, panics in phase 3, and `eject()` launches `pilot_pod.gd` (rocket, parachute, fist shaking) into the FX layer.
  - The rigs: stage 1 `rig_dreadnought.gd` (T-rex), 2 `rig_scorpion.gd` (raptor), 3 `rig_wyvern.gd` (pterodactyl), 4 `rig_mantis.gd` (triceratops), 5 `rig_seraph.gd` (stegosaurus), 6 `rig_skull.gd` (spinosaurus), 7 `rig_kraken.gd` (plesiosaur), 8 `rig_medusa.gd` (dilophosaurus). Stage-module bosses (9+) keep their painted frames with a pilot on top (`GameEnemy._add_frame_pilot`: the canopy straddles the first solid row of the silhouette a little ahead of centre; the species comes from the stage id), with the same reactions and escape pod. The smoke test (`_smoke_check_boss_rigs`) checks every rigged boss uses its rig with a pilot, has its muzzles (`SMOKE_RIG_MUZZLES`), fires every pattern, runs every reaction and ejects a pod that frees itself, and that every module boss has a pilot that bails out; add a new rig's muzzles there. To look at rigs without playing, render them with `boss = null` and `debug_next` / `debug_phase` set.
- `ShipArt` (`scripts/ship_art.gd`, also called from `PixelArt._build_all`) holds the 10 newer ships, their shots, orbit pods and badges as strings with a 1-px dark outline (`q`); edit them like any `PixelArt` sprite.
- `EnemyArt` (`scripts/enemy_art.gd`, a `class_name` called from `PixelArt._build_all`) builds the stage enemies and their special shots, partly from strings and partly painted (`_ball`, `_disc`, `_line`), and adds a 1-px dark outline in `_finish()` so they read against busy backgrounds. Keys start with `en_`.
- **Lookups fail silently.** `PixelArt.tex("typo")` returns the `scout_space` sprite. `RetroSfx.play("typo")` does nothing. A wrong key won't produce an error, so look at the result on screen. (Stage modules' `set_texture()` and background `tex()`/`layer()` do report missing keys, and the smoke test fails on them.)
- `GenesisMusic._process` synthesizes every sample in GDScript on the main thread, with a buffer of only 0.14 s. Keep the per-sample path (`_synth_*_frame`, `_tick_*`) cheap. Any work added there runs 44,100 times per second.
- **Soundtrack slots and alternatives.** Music plays in one slot per place it plays (`GenesisMusic.get_slot_keys()`: `title`, `stage_1`–`stage_<N>` for every stage including modules, `boss`, `hyperspace`). Each built-in slot has its original track plus 5 alternatives in `scripts/music_candidates.gd`; a module's slot has its song plus any `get_song_alternatives()`. They're picked in **Options → SOUNDTRACK** (`main._build_soundtrack_ui`, state `SOUNDTRACK`; 11 rows on screen, the list scrolls with the cursor) and saved as `MetaSave.music_picks` (slot → index, 0 = original). `GenesisMusic.DEFAULT_PICKS` sets the shipped choice for players who haven't picked. `_resolve_song` picks the song for each slot; `preview()` / `resume_after_preview()` are for the picker.
  - An alternative is a song dictionary like `STAGE_SONGS`, with a few extras. `"style"` is the groove: 0–8 are the original stage grooves, and 9–17 add chiptune, drum & bass, outrun, orchestral, ambient, lo-fi, bossa nova, industrial and 6/8. `"bass"`, `"pad"`, `"arp"` and `"lead"` borrow any instrument voice; voices 9+ are extra instruments. `"kit"` sets the drum tuning. The voice list is at the top of `music_candidates.gd`.
  - Melodies are composed at load time from `"seed"` by `GenesisMusic.compose_melody`, unless the entry spells out `"mel_a"`/`"mel_b"`. Change the seed to get a different tune with the same arrangement.
  - Hyperspace alternatives (`"hyper"`) are 2.6 s jingles made of per-16th-step lists (`h_arp`, `h_lead`, `h_kick`, ...).
- **Recorded tracks.** An MP3 in `assets/music/` can take over a soundtrack slot through an entry in `scripts/music_tracks.gd` (`TRACKS`: slot → name, info, file, `bpm`, `loop_start`/`loop_end` as sample positions at 44.1 kHz). The title screen plays Matthew's `title.mp3` and stages 1–5 his `level 1.mp3` … `level 5.mp3` this way. A recording plays on `GenesisMusic._file_player` (an `AudioStreamPlayer`; the generator is stopped and `_process` skips the synth), is the slot's default (`get_pick` falls back to it ahead of `DEFAULT_PICKS`), and is listed in the picker after the slot's alternatives (`recording_index`), so the synth tracks stay pickable. When a slot first gets a recording, `MetaSave.load_game` drops the pick saved for it once: saves list the slots that had a recording (`"music_recordings"`).
  - The song plays from the top once, then repeats `loop_start..loop_end`: `recording_stream()` sets `loop_offset` and expresses `loop_end` through `beat_count`/`bpm` (AudioStreamMP3 loops after `beat_count` beats). Godot crossfades only 256 samples, so pick two downbeats a whole number of bars apart with the same music before both (or a near-silent stop before the end point), each a few ms before the transient. Measure them on Godot's own decoder (`AudioStreamPlayback.mix_audio` in a headless script); its sample positions differ from other decoders'. The smoke test checks each recording jumps from `loop_end` to `loop_start` to the sample.
  - The recordings are about as loud as the synth (RMS ~0.19 vs 0.17–0.22), so they share its volume and pause duck. Commit each MP3's `.import` file (`--import` makes it).
  - Every song, originals included, also gets the arrangement layers from `GenesisMusic._trigger_layers`. Those are crash cymbals at section changes, claps on the groove's backbeat, ghost 16th hats in the gaps, a snare roll into the chorus, a chorus countermelody, plus a sub-octave under the bass, extra bass gain and a punchier kick. How busy they get depends on `energy` (0 calm, 1 normal, 2 intense; defaults per groove in `GROOVE_ENERGY`). `bass_gain`, `sub_mix`, `kick_gain` and `counter` tune them per song.
  - Changing the shared voice, kit or layer code changes every track. To check a refactor is sound-neutral, render the songs before and after (fresh `GenesisMusic` with a fixed `_rng.seed`) and compare the bytes.

## Adding a stage

Every stage after the 8 built-in ones is a **stage module**: one folder, `scripts/stages/<NN>_<id>/` (NN = the stage number), that plugs into the game through hooks. Shared code calls into the module; a module never edits `enemy.gd`, `main.gd`, `starfield.gd` or `genesis_music.gd`. `scripts/stages/09_example/` is a complete, commented **template** ("TEST RANGE": 2 enemies, a boss, a background, a song). It is not in the registry, so it never appears in a run; the smoke test registers it to prove the system end to end.

1. **Copy** `scripts/stages/09_example/` to `scripts/stages/<NN>_<id>/` and delete the copied `*.uid` files (Godot makes new ones on `--import`; copied UIDs would clash). The scripts preload each other with relative paths, so the copy works as is.
2. **Rename** the stage: set `ID` in `stage.gd` and replace every `"example"` key prefix (sprite keys such as `"example_orb_0"`, `"boss_example"`) with your id. Every sprite key must contain the id, and stage ids must be unique.
3. **Write the stage**, file by file. The base classes in `scripts/stages/` document every hook and helper:
   - `stage.gd` extends `stage_module.gd`: the stage table entry (`get_stage_def`: name, subtitle, boss name, palette, `has_ceiling`, generic-enemy skins, boss frame key, bullet textures), the difficulty row (start from the previous stage's and only get harder; `hp` is `1.34^(N-1)`), `get_boss_hp`, the enemy table (`get_enemy_defs`: stats, hit shape, sprite, behaviour script), wave recipes (`queue_themed_group` through a `WaveBuilder`: `w.recipe` 0–2, `w.extra`, `w.spawn(kind, at, pos, ...)`, `w.spawn_generic(...)`, `w.new_squad(n)`), and the song (`get_song`, a `music_candidates.gd`-style dictionary; melodies come from `"seed"`; optional `get_song_alternatives` for the soundtrack picker).
   - One behaviour script per enemy kind, extending `stage_enemy.gd`: `setup`, `tick(delta)`, `draw` (telegraphs, drawn over the sprite), `on_death`, `modify_damage`, and `warn_timer` / `on_wake` / `draw_warning` for an entrance telegraph. Helpers: `shoot_aimed`, `emit_bullet`, `fire_cd`, `spawn_child` (children give no Scrap; cap them), `set_texture` (reports missing keys). GameEnemy (`Type.MODULE`, `module_kind`) handles stats, exits, rewards, status effects and the hold-fire-until-on-screen rule.
   - `boss.gd` extends `stage_boss.gd`: `attack(rate_mult, spd_bonus)` fires one attack and must call `wait(seconds)`; `pattern` (0–2), `substep`, `phase` (1–3) and `spin` drive the patterns. GameEnemy runs the intro, movement, frames, phases, escorts and death.
   - `art.gd`: a static `build(id)` returning key → `Image` for every enemy sprite, special shot and the boss frames `boss_<id>_0/_1/_2`. It runs on a worker thread, so only touch Images (`scripts/stages/art_kit.gd` and BossPainter's static helpers are safe).
   - `background.gd` extends `stage_background.gd`: a static `paint()` returning the still layers as Images (worker thread; use the `stage_bg_painter.gd` primitives), plus `reset`/`update`/`draw` for the animation (`layer(key, y, factor)`, `drift_a`, `fx_spawn`...). The floor/ceiling decks and the hyperspace tunnel are drawn over it. Keep the y 30–249 playfield dark.
4. **Register it**: put `"res://scripts/stages/<NN>_<id>/stage.gd"` on the empty line under `# --- stage <NN>` in `scripts/stages/registry.gd`. Each slot sits between marker lines so parallel batches don't conflict; empty slots are skipped (later stages move up until the gap is filled).
5. **Run the smoke test** in a scratch copy (it wipes the save). For every registered module plus the example it checks: the tables validate (`StageData.validate_module`), the name fits the HUD at a two-digit boss wave (keep names to about 12 characters), every sprite it refers to exists and carries the stage id, each enemy kind runs its behaviour (home stage and first loop, both variants), a kill pays out once and children give no Scrap, the boss gets through its intro, fires, reaches phases 2 and 3 and dies, the background activates and animates, the song and its alternatives render audible audio, its soundtrack slot exists, the wave director queues its own enemies in waves 1–3 and the boss in wave 4, and finally every module background, enemy (sampled at several ages) and boss is drawn in a real frame with no missing sprite or layer. The generic per-stage loop also spawns everything on every registered stage. Then look at it: the smoke test can't judge the art or the patterns.

How it plugs in: `StageData` loads the registry's modules on worker threads once the main scene is up (no boot cost) and appends their rows to `stages`/`difficulty`; anything that needs them earlier registers them on the spot. A stage's sprites are built on a worker thread by `StageData.prefetch_stage()` while the previous stage plays (`main._begin_next_wave` asks for the next stage), and its background layers by StarfieldBg's existing prebuild, so the hyperspace jump into a module stage costs about as much as one between built-in stages (both well under a millisecond on the Mac mini). `GameEnemy` creates the module's behaviour and boss objects; `main._queue_themed_group` hands module stages a `WaveBuilder`; `StarfieldBg` uses the stage id as the theme key and calls the module's painter and background object; `GenesisMusic` builds the module song like an alternative track and adds a `stage_<N>` soundtrack slot.
